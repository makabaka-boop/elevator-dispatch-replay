# 离线电梯群控模拟器

使用 **Svelte + TypeScript + Vite** 构建的完全离线、确定性离散事件电梯群控模拟器。

## 功能范围

- 支持 **3～16 层**、**2～4 台电梯**。
- 每台电梯容量固定为 **6 人**。
- 最多输入 **100 个请求**，每个请求包含：
  - 到达 tick
  - 出发层
  - 目的层
  - 人数（1～100）
  - 可选取消 tick
- 可配置固定整数耗时：
  - 行驶一层耗时 `travelTicks`
  - 开门耗时 `doorTicks`
  - 关门耗时 `doorTicks`
  - 门完全打开后保留 1 个离散 tick 用于上下客
- 门处于开门中、门开、关门中时不能行驶。
- 容量不足时只上可容纳人数，其余乘客保留等待；不会从状态中消失。
- 只有尚未上车的人可以取消；已上车的人必须送达。
- 页面支持播放、暂停、单 tick、跳转、0.5×/1×/2×/4×/8× 变速播放。
- 变速和跳转只读取预先计算并冻结的快照，不重新计算另一套状态。

## 群控规则

新请求到达时，对每台电梯进行 ETA 推算：

1. 复制该电梯当前阶段、楼层、方向、剩余 tick、已承诺上客点和车内乘客下客点。
2. 把新请求的出发层作为候选上客点，以确定性的 SCAN 路线插入。
3. 在候选路线中模拟当前未完成门动作、已承诺停靠、满载跳过、下客释放容量、关门和行驶。
4. 同 tick 较早 ID 的请求先形成“假设承诺”，后续请求的 ETA 会扣除它们将占用的容量。
5. ETA 表示该电梯门完全打开，且新请求至少第一批人在容量上可上车的 tick。
6. 选择 `ETA` 最小的电梯；ETA 相同选择电梯 ID 最小者。

ETA 只用于派车决策；实际状态仍由同一个离散事件引擎推进。

## 确定性状态模型

每个 tick 内顺序固定：

1. 处理本 tick 生效的取消。
2. 记录本 tick 到达的请求。
3. 对未派车请求按请求 ID 排序并依次派车。
4. 推进所有电梯状态。
5. 保存本 tick 的不可变快照。

电梯路线不是单独输入的可变数据，而是持续从以下承诺重建：

- 车内乘客的下客楼层；
- 已派给该车、仍未上车者的上客楼层。

因此取消、部分上客、满载暂跳过上客点等情况不会产生幽灵停靠点。

## 运行

```bash
npm install
npm run dev
```

生产构建：

```bash
npm run build
npm run preview
```

## 测试

```bash
npm test
```

测试覆盖：

- 同时到达请求的 ETA 并列与最小电梯 ID 决策；
- 基于当前已承诺停靠点的派车；
- 容量 6 人导致的部分上客与剩余请求保持；
- 未上车取消、部分取消、已上车取消被拒绝；
- 开门/门开/关门期间禁止行驶；
- 每个 tick 的人数守恒；
- 快照应不可变；
- 不同播放速度、跳转、倒回读取的是同一份逐 tick 快照。

## 项目结构

```text
src/
  components/
    BuildingView.svelte       # 楼层、电梯、等待区可视化
    PlaybackControls.svelte   # 播放、跳转、变速控制
    RequestEditor.svelte      # 请求表格编辑
  lib/
    engine.ts                 # 确定性离散事件引擎与群控算法
    engine.test.ts            # 引擎逐 tick 回放测试
    playback.ts               # 只读取快照的播放器
    playback.test.ts          # 不同速度和跳转一致性测试
    sample.ts                 # 默认示例
    types.ts                  # 类型定义
  App.svelte
  main.ts
```
